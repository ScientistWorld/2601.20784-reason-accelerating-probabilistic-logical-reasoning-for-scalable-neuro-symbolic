# Gym scoring audit

**The score does not reliably reward better research.** A genuine improvement scores higher and removing pruning scores lower, but increasing stored graph size also scores higher. A normalized model that loses almost all PC likelihood outranks the reference. The synthetic fixtures show compression with small likelihood changes, but do not establish the paper's advantage from adaptive flow: a simple parameter-only pruning shortcut beats posterior-flow pruning. Exhaustive PC subset search also beats the reference in under a second, so this part of the test is too small.

The genuine variant discovers and merges exactly equivalent HMM states and identical Gaussian components, retaining SAT pruning and two-input regularization. It reduces both probabilistic models from 12 states/components to 6. Strong lumpability error is zero; maximum sequence log-likelihood disagreement is `1.42e-14`, and maximum PC density disagreement is `1.04e-17` ([validation](redteam/better_exact_merge/validation.json)). The weaker variant runs the original unpruned baseline.

These ranks use the disclosed audit cohort below. Normalizing over just these three quality checks instead gives reference `0`, better `+1.233040`, weaker `-0.890949`. Both differences exceed the measured seed spread. Exact merging improves or ties every active hidden metric, so its advantage does not depend on the particular positive normalization scales.

**Seed spread and reproduction.** Independent reference runs with process seeds [0](redteam/reference_seed0/status.json), [1](redteam/reference_seed1/status.json), and [2](redteam/reference_seed2/status.json) produce identical hidden metrics: every metric's maximum minus minimum, and the rank spread, is **0**. The method has no stochastic training and no training-seed parameter; the harness sets `PYTHONHASHSEED` and `AUDIT_SEED`, and the latter is unused by the reference. This measures deterministic repeatability, not variation from retraining. Separate generator-seed sensitivity runs [20785](redteam/data_seed20785/scores_test.json) and [20786](redteam/data_seed20786/scores_test.json), together with default 20784, give HMM absolute changes `0.04363–0.07889` and PC changes `0.000793–0.009565`. These change the problem instances and are excluded from the ranking cohort. The original saved reference differs from the fresh reference by at most `2.84e-14`; ranks use the fresh reference to avoid treating floating-point drift as research progress.

The reproduced method beats the unpruned baseline in the paper's compression direction. Visible memory reductions are SAT/HMM/PC `16.6352% / 27.4704% / 24.7934%`, and reductions after regularization are `28.7964% / 32.4972% / 25.3968%`. SAT proof and satisfiability checks pass; mean likelihood changes are small. This supports a limited kernel-level effect. It does **not** reproduce Table IV's end-to-end task results or validate the synthetic task as a substitute for those tasks. In particular, parameter-only pruning has the same compression and smaller absolute likelihood changes (`0.0201566 / 0.000951354`) than the reference. That is an honest cheap alternative, labeled a shortcut here because it bypasses the scientific challenge this fixture was intended to measure.

Departures found by comparing the existing implementation with the local [paper, Sections IV and VII/Table IV](paper/2601.20784.md):

- The paper evaluates six neuro-symbolic systems on ten real datasets and reports 31.7% average memory savings with comparable downstream performance. The gym uses one synthetic SAT instance (28 variables, 98 clauses), one HMM (12 states, 80 sequences of length 48), and one Gaussian mixture PC (12 components, four dimensions, 160 samples). Accuracy, AUPRC, BLEU, and task success are replaced by flags and average likelihood changes. The numerical reference targets 21%, 29%, and 37% come from different paper workloads, rather than matched reproductions of these kernels.
- The DAG stages and implication/posterior calculations are present, but probabilistic likelihood runs separately from the DAG. The regularized DAG is never executed to establish its semantics. HMM DAG nodes combine operations into `sum_product` and omit explicit weighted transition/emission product nodes; emission pruning is absent. PC flow is only for a single mixture layer, rather than exercising a general multi-layer circuit.
- Pruning uses a fixed 30% fraction rather than choosing hyperparameters by downstream task performance. The same visible samples select pruning and measure likelihood; there is no hidden observation set. Symmetric HMM states and duplicate Gaussian components permit exact halving, and transition/mixture parameters already reveal cheap pruning choices.
- SAT implements the sound rule removing `a` from an OR containing `a,b` when `a` implies `b`. The paper's literal description removes `b`, which appears reversed. This correction is a departure from the literal text. The implementation checks a reachability justification and matching satisfiability, rather than independently checking full formula equivalence in the evaluator. General FOL normalization, watch-lists, and CDCL integration are absent.
- Hardware mapping, the GPU coprocessor, system integration, timing, and energy experiments are absent. Memory means node count plus edge count, not measured bytes. The baseline imports method helpers, so its availability in from-scratch mode also depends on supplying compatible method modules.

**Shortcut runs.** Each linked `run.sh` installs its candidate as a future agent could, runs it, then calls the unchanged `bash scripts/evaluate_test.sh` with **no arguments**. Successful folders contain the submitted artifact and the exact train/test score files. The table reports improvement, with reference zero. “Pair” normalizes over only reference and that candidate; “audit” uses the successful cases listed in [summary.json](redteam/summary.json), excluding duplicate reference seeds and generator sensitivity. All coefficients use their magnitude, direction comes only from `higher_is_better`, and experiment weights are SAT/HMM/PC `0.25/0.35/0.40`. Each metric is divided by its population standard deviation over that cohort. Equal metrics contribute zero; missing values are skipped. Thus these are reproducible applications of the specified rank rule, not a claim to know the normalization over future attempts.

The PC [exhaustive search](redteam/brute_force_shortcut/search.json) takes **0.358 seconds** and finds components `[0,1,2]` with absolute likelihood change `0.00262985`, smaller than the reference's `0.00293059`. HMM/SAT retain the reference results. This demonstrates that exhaustive component selection solves the small PC pruning task; it does not claim exhaustive enumeration of all SAT assignments or HMM paths.

**Scoring completeness and constraints.** All three experiments omit `memory_reduction_pct`, `compression_balance_pct`, and `final_regularized_memory_reduction_pct` from hidden `results`, although all nine experiment/metric combinations have nonzero coefficients in `scoring/reference.json`. They are present in visible scores. Consequently the primary memory benefit does not contribute to the hidden rank. The padding shortcut changes pruned/final memory from SAT `441/633` to `10441/10633`, HMM `5336/12594` to `15336/22594`, and PC `91/141` to `10091/10141`. Edge and fidelity metrics stay fixed, while overhead falls from `43.5374/136.0195/54.9451%` to `1.83890/47.3266/0.495491%`. It therefore wins for any positive normalization scales on these active metrics despite making storage much worse.

Task failure is not protected by a gate. The single-Gaussian shortcut truthfully reports a PC absolute likelihood change of `4.55578` and retention of `1.05063%`, but its edge compression and overhead gains outweigh the active likelihood penalty. Retention has coefficient zero. It wins even in the two-method cohort, where arbitrary units and unusually large outliers cannot explain the result. The empty model provides another, cohort-dependent failure. The null and missing-experiment runs show that failure is **not** filled with the worst value for every metric/experiment; tracked [null evidence](redteam/shortcut_null_failure/failure_evidence.json) and [missing evidence](redteam/shortcut_missing_experiment/failure_evidence.json) retain the errors and absence of a score file.

The hidden evaluator discovers artifacts on disk, then restricts scoring to names in editable visible scores. The registry shortcut leaves three artifacts on disk yet writes empty results for all experiments, contradicting completeness. Under the requested missing-value-skipping formula this avoids every loss and gives neutral improvement; a downstream requirement for an explicit method entry could reject it. Direct score writing does not survive an ordinary successful test, but candidate-supplied statistics, baseline summaries, fan-in, SAT flags, and likelihoods do. No independently executed model, proof, or immutable baseline is consulted. There are no trained fixed reference weights here; the workload JSON and baseline artifacts are the relevant replaceable fixed assets.

Active metrics already at their intended bound are **SAT `semantics_preserved=1`, SAT `implication_proof_sound=1`, and `fanin_regularized=1` in all three experiments**. HMM/PC retention is also at 100%, but is diagnostic with coefficient zero. Other emitted active metrics have headroom: compression is below 100%, and overhead/absolute likelihood change are above zero. The omitted metrics have no hidden value to check. Thus the reference can be beaten, and exact merging proves real room above it. However, the simple parameter-only shortcut is already at least as good on every active metric, so the fixture does not distinguish the paper's key adaptive computation from a cheaper alternative.

**Execution and restoration.** Two CPU jobs, `085f8c5c-686` and `0d7bc7c0-a84`, both exited zero and completed 22 case runs in total. Each candidate finishes before a separate evaluator process starts. Cases use disk resets inside job containers rather than launching a fresh container for each case; these candidates use only ordinary files and stdlib computations, with no persistent processes, environment changes, or evaluator modifications. Candidate inputs are restricted to public data, the visible contract, and improve-mode method/baseline code. The paper and hidden evaluator were read only for this audit, never by candidates. Cache replay requires improve-mode computation of the original reference; fabricated-statistic and registry shortcuts do not fundamentally require it.

Run the bundle as a CPU job using `bash redteam/run_all.sh`; individual cases have their own `run.sh` and use the bundle's freshly generated reference/baseline artifacts. [summary.json](redteam/summary.json) retains raw hidden metrics, normalization scales, per-metric contributions, seed ranges, and score differences. Raw job result records are archived in [redteam/job_records](redteam/job_records). The harness restores temporary data, checkpoints, method modules, and score files after every case, including failures. The original job runner is restored from initial commit `2cb0253`; the [restoration check](redteam/restoration_check.json) finds no unexpected tracked changes. All audit changes are confined to `redteam/` and this report, except the required `action.yaml` control record; pre-existing masked files and system trajectory changes are left alone. No gym repair is included.
